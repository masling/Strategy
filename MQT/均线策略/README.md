# QMT 内置 Python：多周期大盘择时与行业轮动策略

这是一版用于 QMT 回测和模拟验证的日频策略。它不依赖 MiniQMT，也不需要外部 Python 进程。

> 仅用于策略研究和模拟测试，不构成任何投资建议。默认配置为 `BACKTEST`，复制到 QMT 后不会主动向模拟账户发委托。

## 策略做什么

| 层级 | 规则 |
|---|---|
| 大盘状态 | 综合沪深 300、中证 500、中证 1000、创业板指的日线、周线和月线趋势 |
| 仓位上限 | 安全分映射为 0%、25%、45%、65%、80% |
| 行业选择 | 使用 `SW1...` 申万一级行业成分股，按每日个股收益率等权合成行业代理曲线，再计算 20/60 日相对强弱、趋势、成交额和过热惩罚；最多 3 个行业 |
| 个股选择 | 行业内流动性、MA20/60/120 多头排列、相对行业强度、近期新高距离和波动率排名 |
| 组合限制 | 最多 6 只，每个行业最多 2 只，单只最多 15% |
| 调仓节奏 | 每 5 个交易日重算行业和目标股票；大盘风险和个股退出条件每日检查 |
| 退出规则 | 无最低持有期；市场风险、2 ATR 初始止损、2.5 ATR 移动止损、+12% 止盈、跌破 MA20、行业轮出或持有满 20 日均可退出 |

“5～20 个交易日”是期望的持股节奏，不是强制锁仓。盈利达到止盈线或风险条件触发时，第一个持有日也可以退出。

## 文件

- `qmt_multicycle_strategy.py`：直接复制到 QMT 内置 Python 编辑器的完整策略。
- `tests/test_qmt_strategy.py`：核心计算和关键交易边界的本地单元测试。

## 先准备 QMT 数据

在 QMT 的“操作 → 数据管理”中补充以下数据：

1. 下载“全部板块”分类信息，确保能读取 `SW1汽车`、`SW1电子`等 31 个申万一级行业成分股。
2. 为 `000300.SH`、`000905.SH`、`000852.SH`、`399006.SZ` 下载日线。
3. 为 `沪深A股` 下载日线；行业代理曲线和个股筛选共用这些成分股行情。策略默认排除科创板和北交所，允许创业板。
4. 不再需要 `迅投一级行业板块加权指数` 或任何 `*.BKZS` 行情。
5. 建议在“过期合约数据”中补充历史 ST 数据，否则历史回测的 ST 过滤可能退化为当前证券名称判断。

周线和月线由 QMT 使用日线合成，因此不必重复下载基础数据。至少保留 3 年日线作为指标预热；例如从 2018 年开始回测，建议从 2015 年或更早开始下载。

## 第一步：回测

1. 在 QMT 新建“Python 策略”，将 `qmt_multicycle_strategy.py` 的全部内容复制进去。
2. 保持文件顶部 `RUN_MODE = "BACKTEST"`。
3. 主图选择 `000300.SH`，周期选择“日线”。
4. 配置回测初始资金、佣金、税费和滑点，然后运行回测。
5. 查看日志中的：
   - `STATE`：大盘安全分、目标总仓位和四个指数分项；
   - `SECTOR_SOURCE`：首次行业计算时输出实际可用的 `SW1` 行业数、去重成分股数和成功读到行情的股票数；
   - `SECTORS`：本次入选行业；
   - `TARGETS`：入选股票；
   - `ORDER`：委托方向、数量和原因。

回测不需要登录名为 `test` 的资金账户。策略通过 QMT 回测专用的
`get_result_records('holdings', ...)` 和 `ContextInfo.get_net_value(...)`
读取虚拟持仓与资产；只有模拟盘才使用 `get_trade_detail_data(...)`
查询已登录账户。

建议至少分别观察上涨、震荡和下跌区间，并对滑点做 0.10%、0.20%、0.30% 三档压力测试。不要只看累计收益，还要检查最大回撤、换手率、盈亏比、单年度表现和空仓时间。

## 第二步：QMT 模拟账户

只有回测结果和日志检查通过后，再进行以下操作：

1. 把 `RUN_MODE` 改成 `"SIMULATION"`。
2. 在“模型交易”中绑定一个专用模拟账户，主图仍使用 `000300.SH`、日线周期。
3. 在 09:35 前启动。策略会在 09:35～14:50 之间每天只执行一次，判断依据为上一完整交易日的数据，委托使用对手价。
4. 第一天只用小额模拟资金，核对股票代码、买卖方向、目标股数和日志原因。

重要：QMT 的“模拟信号模式”只记录信号，不向账户报单。如果要让券商模拟柜台实际接收委托，需要在确认绑定的是**模拟账户**后，以 QMT 的交易执行模式启动。不要绑定真实资金账户。

建议使用专用模拟账户，不要与人工持仓混用。策略会识别本策略产生的成交，但客户端重启后，对更早历史持仓的归属和持有天数恢复能力有限。

## 常用参数

都在策略文件顶部：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `REBALANCE_EVERY` | 5 | 行业和股票池重算间隔 |
| `TAKE_PROFIT_RATE` | 0.12 | 浮盈 12% 立即止盈；设为 0 可关闭 |
| `MAX_SECTORS` | 3 | 最大行业数 |
| `MAX_STOCKS` | 6 | 最大股票数 |
| `MAX_PER_SECTOR` | 2 | 每行业最大股票数 |
| `MAX_STOCK_WEIGHT` | 0.15 | 单股仓位上限 |
| `MIN_AVERAGE_AMOUNT` | 50000000 | 20 日平均成交额下限，单位元 |
| `ALLOW_CHINEXT` | `True` | 是否允许创业板 |
| `ALLOW_STAR` | `False` | 是否允许科创板 |
| `ALLOW_BSE` | `False` | 是否允许北交所 |

第一轮模拟不要同时优化大量参数。优先验证数据完整性、委托行为、风控触发和策略在不同市场阶段的稳定性。

## 已知限制

- QMT 内置接口读取的是当前行业成分，因此行业代理曲线和历史选股都存在成分穿越与幸存者偏差。应把向前模拟作为主要证据。
- 国金 QMT 不提供迅投 `BKZS` 行业指数时，策略用成分股日收益率等权合成代理曲线。它用于横向强弱排名，不会与官方申万市值加权指数完全一致。
- 内置 Python 策略依赖 QMT 客户端、Windows 电脑和网络持续运行。
- 策略重启会重建内存状态；已有持仓的成本可从账户恢复，但持有天数和历史最高价会从重启时重新累计。
- 这是日频/低频版本，不适用于 Tick 抢单、打板或高频套利。

## 本地验证

```bash
python -m unittest discover -s "MQT/均线策略/tests" -v
python -m py_compile "MQT/均线策略/qmt_multicycle_strategy.py"
```

核心计算可在普通 Python 中测试；QMT 的账户、行情和报单对象只能在客户端内完成最终运行验证。
